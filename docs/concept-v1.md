# 構想 — onomato-atlas(音象アトラス)

日本語オノマトペの**音韻素性から意味への写像**を可視化する静的 Web アプリ。
辞書引きアプリにはしない。「音そのものが意味を運んでいる」ことが**目で見えて、かつ反証可能**であることが成果物の全て。

---

## 0. 前提となる会話からの変更点(先に差分を明示する)

元の構想(三層構造・Vercel 判断・段階スコープ)はそのまま骨格として採用する。
そのうえで、フリートの流儀に載せるために **4 点を変更**した。理由も併記する。

| # | 元案 | 変更後 | 理由 |
|---|---|---|---|
| 1 | `onomato-lens` | **`onomato-atlas`** | フリートの命名は `-lens`=定期収集ダッシュボード(koho/kiban/kasumigaseki/hyakunin/saijiki)、`-atlas`=一次資料の俯瞰地図(kiko/makura/hojoki/tsurezure/jikenbo/ango)、`-lab`=実験工房。本案は cron 更新のない俯瞰地図なので `-atlas` が整合する |
| 2 | 素性表(k=硬/乾, g=重/濁 …)を**所与のデータ設計**として提示 | 素性表は**検証対象の仮説**として提示 | 素性→意味の対応は本アプリが主張する内容そのもの。入力に書いて出力に取り出すと、何も検証していない循環になる |
| 3 | 語彙は「300語の素性DB」から出発 | 語彙リストを**青空文庫コーパスから実測抽出**して出発 | 擬音語辞典の見出し語リストは選択・配列に創作性が及びうる。コーパス抽出なら権利が clean で、かつ頻度という実測量が同時に手に入る(kiko-atlas の実測主義と同じ) |
| 4 | v0.3 の逆引きを Claude API に載せる | 逆引きは**クライアント完結**、生成のみ API | 逆引き=素性距離の最近傍探索。API を挟む必要がない。API 依存を「未登録音形の語釈生成」1 点に隔離すると、v0.4 まで完全静的で走れる |

## 1. 体験の核(一文)

**「ころころ・ころっと・ころり・ころん」を散布図の上に並べると、4 点が一直線に並ぶ。**
語幹が同じで形態だけが違う語は、5 軸のうち「瞬間⇔持続」軸**だけ**が動くはずだから。
これが本当に起きるかどうかが、このアプリが本物かどうかの判定そのものになる。

---

## 2. 検証オラクル — 本案の背骨

オノマトペの語感には「正解ラベル」が無い。だが**語彙の内部対称性そのものが、ラベル無しの正解対**になる。
ango-atlas の O-1(二重版一致)、kokoro-graph の言語間一致と同型の構造がここにある。

### O-1 形態パラダイム不変性(最重要)

同一語幹の形態バリアント(`ころころ / ころっと / ころり / ころん`)は、
**「瞬間⇔持続」軸のみが有意に動き、他 4 軸は動かない**。

- 対はコーパスから自動生成できる(語幹が一致し、接辞形が異なる語をグルーピング)
- 他軸が動いたら、素性抽出が形態と音質を分離できていない = 特徴量の欠陥
- 人手ラベルゼロで数百対が得られる見込み

### O-2 濁音ミニマルペア単調性

`からから / がらがら`、`さらさら / ざらざら`、`きらきら / ぎらぎら`、`ころころ / ごろごろ`、
`とんとん / どんどん`、`ぱらぱら / ばらばら` ——
**濁音化した側が「重い」「粗い(硬)」方向へ単調に動く**。方向は先行研究で一貫している知見であり、
本アプリが独自に主張するものではない。だから外部整合の検定に使える。

- 全ペアで方向が揃うか、揃わない例外は何語か、を**数で報告する**(「概ね揃う」は書かない)

### O-3 外部整合(ブーバ/キキ)

Köhler(1929)の maluma/takete、Ramachandran & Hubbard(2001)の bouba/kiki は、
破裂音+高前舌母音 → 尖鋭、共鳴音+円唇母音 → 円滑、という方向が確立している。
日本語オノマトペに写した場合の予測方向を**事前登録**し、後から実測と突き合わせる。
※ 事前登録が肝。散布図を見てから「効いていた」と言うのは循環。

### O-4 二実装一致

素性抽出とスコアリングを Python(工房)と TypeScript(店先)の**両方に実装**し、
同一フィクスチャで完全一致を縛る。kokoro-graph の移動平均・nanpure-forge の PRNG と同じ手。
逆引きをクライアント計算にする設計判断が、この二重実装を**必然**にする(仕様の副産物ではなく要件)。

### O-5 賢治造語ホールドアウト

宮沢賢治の造語(`かぷかぷ`『やまなし』、`どっどど どどうど`『風の又三郎』など)は
**訓練に一切使わない**。既存語だけで作った写像に後から流し込んで、
既存語の分布の**内側**に落ちるかを見る。落ちれば「新語は規則の内側で作られている」が実証される。
落ちなければ、それはそれで報告する(規則の外の造語という発見)。

> これが v0.2 の目玉の画になる想定だが、**外れた場合も外れたまま公開する**。
> 期待した画が出なかったことを隠すために閾値をいじらない。

## 3. 較正ファースト

kyokai-lab / kokoro-graph / kyoka-grid で繰り返し踏んだ轍を先回りする。

- **較正前に閾値・合格ラインを SPEC に書かない**。O-1〜O-3 の許容幅は L2 の実測を見てから決める
- 5 軸(硬⇔柔/軽⇔重/瞬間⇔持続/乾⇔湿/快⇔不快)は**独立とは限らない**。
  PCA の寄与率で実次元を測り、「5 軸と言いつつ実質 2 次元」ならそう表示する。
  軸を 5 本に見せるために回転を選ばない
- kokoro-graph の擬古文問題と同型のリスク: 古典作品のオノマトペは現代語と語感がずれる。
  コーパスの年代分布を出し、制約を UI に明示する

## 4. 三層構造(元案を継承・役割を整理)

### 第 1 層 素性 — 決定論部と仮説部を分ける

ここが元案から一番効く整理。素性抽出は 2 つに割れる。

- **決定論部**: 語頭子音・母音・形態型(ABAB / ABっと / ABり / ABん / AB—)・濁音半濁音・促音撥音長音。
  これは表記から機械的に取れる。人手不要・数千語に即スケールする
- **仮説部**: 素性 → 5 軸スコアの重み。**これだけが主張**であり、O-1〜O-3 の検証対象

→ 帰結: **散布図は数千語で描ける。300 語に絞る理由は素性ではなく「語釈を自前で書く手間」**。
v0.1 のスコープを「素性散布図=全抽出語 / 語釈付き詳細ページ=300 語」に割ると、
初手から見応えのある画が出せる。

### 第 2 層 用例(青空文庫)

kokoro-graph の bronze 取得・正規化パイプラインをほぼそのまま流用できる。
yamato-gaze の**引用二層原則**(表示層は逐語一致・分析層は正規化済み・底本表記必須)を規律として持ち込む。

### 第 3 層 生成・逆引き

- **逆引き(文 → オノマトペ候補)**: 素性距離の最近傍。クライアント完結・API 不要・オフラインで動く
- **生成(素性スライダー → 未登録音形 + 語釈)**: ここだけ Route Handler → Claude API。
  よく使われる組み合わせはビルド時に事前生成してキャッシュに置き、API 呼び出しを減らす

## 5. Vercel 前提の技術判断

元案の表を継承。変更・追記のみ記す。

| 論点 | 方針 |
|---|---|
| 形態素解析・コーパス走査 | 実行時にやらない。ローカルで実行 → JSON をコミット(フリート標準) |
| 解析器 | **fugashi + unidic-lite**(yamato-gaze / kokoro-graph と同一)。SudachiPy 併用は L1 で必要性を実測してから |
| 次元圧縮 | ビルド前計算・座標のみ配信。PCA は numpy 自前実装で足りる見込み |
| データ配信 | 素性+座標は全載せ。用例が万単位なら**語ごとに分割 JSON + 遅延ロード**(ango-atlas と同型)。Turso は最後の手段 |
| 検索 | クライアント側。語数が数千なら追加ライブラリ不要 |
| 生成 API | v0.6 まで導入しない。導入時も Route Handler 1 本に隔離 |
| SEO | `/o/ふわふわ` を静的生成。**URL の日本語エンコードとファイル名衝突を L4 で実測**(濁音の合成/結合文字ゆれが刺さる可能性) |
| デプロイ | Next.js 静的 export・Root Directory = `web`。**着手前に `onomato-atlas.vercel.app` の空きを確認**(kokoro-graph / app-menu で他者取得済みに二度当たっている) |
| app-menu | 完成時に「文学・翻訳」カテゴリへカード 1 枚追記 |

## 6. 権利

- **語釈・素性付与・5 軸定義はすべて自前**。既存の擬音語辞典から語釈を持ち込まない(元案の指摘どおり)
- **語彙リストもコーパス実測で自前生成**する(§0 の変更 3)。辞典の見出し語リストに依存しない
- 青空文庫本文は PD。底本・入力者・校正者の表記を引用に必ず付す
- ライセンス二層: コード MIT / 自作データ CC BY 4.0(yamato-gaze・kokoro-graph と同構成)

## 7. ループ計画

| ループ | 内容 | 完了条件 |
|---|---|---|
| L1 | コーパス探査・語彙抽出 | 青空文庫から ABAB/ABっ/ABり/ABん/AB— 型を実測抽出。語数・頻度分布・年代分布を**数で**確定。SPEC の語彙規模仮定を実測で置換 |
| L2 | 素性抽出器(決定論部)+ オラクル対の自動生成 | O-1 の形態パラダイム、O-2 の濁音ペアがコーパスから何組取れたかを報告。O-3 の予測方向を**事前登録** |
| L3 | 意味写像 + 較正 | 5 軸スコアリング・次元圧縮。O-1〜O-3 を実測し、**ここで初めて**ゲート閾値を決める。PCA 寄与率を公開 |
| L4 | UI + 公開 | 散布図・フィルタ・語ページ静的生成。Vercel 公開。app-menu 掲載 → **ここまでが v0.1** |
| L5 | 用例層 | 実例・作家プロファイル・賢治造語の重ね(O-5) |
| L6 | 逆引き(静的)+ 生成(API) | 二実装一致 O-4 を縛る |
| L7 | 語感クイズ + OGP 共有 | 未知語の意味当て。正答率を素性距離の関数として記録すると、それ自体が O-3 の追試になる |

v0.1 = L1〜L4、完全静的・API ゼロ。ここで「規則が見えるか」が決まる。

## 8. 未決・リスク

1. **コーパス抽出の再現率**: 形態素解析器はオノマトペを副詞/名詞/感動詞に散らす。正規表現との併用が要るはず。L1 の主要な実測項目
2. **5 軸が実質 2 次元だった場合**: それでもアプリは成立する(むしろ発見)。ただし UI の「5 軸スライダー」は設計変更になる。L3 の結果を待って L4 の UI を確定する
3. **O-1 が破れた場合**: 形態と音質の分離に失敗している。素性設計に戻る。この場合 L4 は進めない
4. **語釈 300 語の執筆コスト**: 自前定義が必須なので削れない。素性散布図と分離したのはこの直列を切るため
5. **母音 e の「非規範的」仮説**(へなへな・でれでれ)は他の母音より根拠が弱い。O-2 のような対称対が作りにくいので、**検証できないなら UI で主張しない**

---

## 9. 一行で

**素性は決定論、意味写像だけが仮説。仮説は語彙自身の対称性(形態パラダイムと濁音ペア)で反証にかける。**
それが通った分だけを散布図に描く。

# 追記 — 事前実測(2026-08-25)

kokoro-graph の青空文庫 bronze(**317 作品 / 13,054,219 字**、うち形態素解析は 100 作品 /
3,659,984 字の標本)に対して実測した。SPEC を書く前に、机上の仮定を数で置き換える。

## 実測 1 — 語彙規模の天井

| 基準 | ABAB 型 異なり語 |
|---|---|
| 全件 | 774 |
| 頻度 ≥ 3 | 479 |
| 頻度 ≥ 10 | 272 |
| 頻度 ≥ 30 | 119 |
| 頻度 ≥ 100 | 23 |

延べ 15,905。**13M 字で頻度 ≥30 は 119 語しかない**。元案の「300 語」は語釈を書く語数としては
妥当だが、統計的に安定した扱いができる語数としては楽観的。

## 実測 2 — 形態素境界フィルタは効く(偽陽性 10.4%)

正規表現のみ 519 語/5,310 件 → 語境界一致 386 語/4,759 件。**延べの 10.4% が部分文字列の偽陽性**。
消えた例: `いていて`(48→0、「置いていて」由来)、`のものも`(18→0)、`らはらは`(「彼らはらはらと」由来)。
変化形はさらに酷く、正規表現だけだと `からん`=291(「わからん」「つまらん」)、
`にやっ`=274(「…にやって」)、`うやっ`=180 を拾う。**語境界なしの抽出は使い物にならない**。

## 実測 3 — 品詞は散らない(私の事前予想が外れた)

ABAB トークンの品詞分布: **副詞 90.6% / 形状詞 5.3% / 名詞 2.5% / 感動詞 1.3%**。
構想 §8-1 で「解析器はオノマトペを副詞/名詞/感動詞に散らす」と書いたが、実測では散らない。
POS フィルタは非常にクリーンで、副詞+形状詞+感動詞で 97.2% を占める。

## 実測 4 — しかし品詞では擬態語を切り出せない(最重要)

語境界一致の上位 20 語:
`とうとう`(371) `なかなか`(273) `わざわざ`(264) `いよいよ`(264) `だんだん`(260) `いろいろ`(241)
`ますます`(99) `そろそろ`(79) `ぐるぐる`(69) `ちらちら`(61) `どんどん`(59) `しばしば`(58)
`たびたび`(55) `ぶらぶら`(54) `にやにや`(54) `ありあり`(49) `ぐずぐず`(40) `ふらふら`(32)
`もともと`(31) `くるくる`(30)

このうち **半数以上が擬態語ではない反復副詞**(とうとう・なかなか・わざわざ・いよいよ・だんだん・
いろいろ・ますます・しばしば・たびたび・もともと)。しかもこれらは**すべて副詞 100%** なので、
**品詞でも頻度でも機械的には切れない**。

→ 結論: **語彙リストは「コーパス抽出 → 人手 curation」の二段が必須**。
§0 の変更 3(コーパスから自前生成)は権利面では正しいが、「自動で clean な語彙が出る」は誤り。
yamato-gaze の「実体辞書は curated のみ・発見語は needs_review にエスカレーション」と同じ規律が要る。

## 実測 5 — オラクル対の収量

- **O-1 形態パラダイム**: 語幹頻度 ≥3 の 479 件中、2 形態以上を持つ語幹 392 件 / 3 形態以上 297 件 /
  4 形態以上 182 件。ただしこの数字は**語境界なしの計測**なので、実測 2 の偽陽性を含む。
  境界フィルタ後の再計測が L1 の必須項目。良好な例: `がさ`(がさがさ/がさっと/がさっ/がさり/がさん/がさーっ)、
  `じろ`(じろじろ 71 / じろり 72 / じろっと)、`ばた`(ばたばた 88 / ばたり 27 / ばたん 9)
- **O-2 濁音ミニマルペア**: 94 組。**両側とも頻度 ≥5 は 30 組**。
  良好な対: きらきら(72)/ぎらぎら(37)、さらさら(72)/ざらざら(32)、からから(37)/がらがら(45)、
  ころころ(25)/ごろごろ(53)、するする(50)/ずるずる(44)、とんとん(27)/どんどん(123)、
  ふらふら(120)/ぶらぶら(153)、くるくる(75)/ぐるぐる(126)
  ノイズ対も混入: たんたん(1)/だんだん(842)、わさわさ(2)/わざわざ(435)、ますます(295)/まずまず(2)
  → curation 後に再計測すれば **20〜25 組**が実用対と見込む

## 実測 6 — 13M 字では足りない

頻度 ≥30 が 119 語、O-2 の実用対が 20〜25 組。統計検定にはぎりぎり。
青空文庫の公開作品は約 17,000 件あり、317 作品は **2% 弱**。ango-atlas で 513 作品の取得実績が
あるので取得パイプラインは流用できる。**コーパス拡大が L1 の最重要判断**。

# 構想の重大な欠陥 — O-1/O-2 は現設計では恒真式になる

上の実測より深刻な問題を、実測の途中で見つけた。**先に直す必要がある。**

## 循環

構想では座標を **座標 = f(音韻素性)** と定義し、そのうえで
「形態バリアントは瞬間⇔持続軸だけが動くはず」(O-1)を検証すると書いた。

しかし f の入力が音韻素性しかないなら、`ころころ / ころっと / ころり / ころん` の間で
**違う入力は形態型だけ**であり、重み表が形態型を持続軸だけに送っている以上、
**他の 4 軸が動かないのは構成上の恒真式**である。O-2 も同じで、濁音重みを「重い」方向に
置いたのだから、濁音ペアがその方向へ動くのは検証ではなく代入結果の確認にすぎない。

つまり現設計の O-1〜O-3 は**何も反証できない**。素性表から作った座標が素性表の構造を
再現しているだけで、「音が意味を運んでいる」の「意味」がどこにも存在しない。

## 直し方 — 独立した二つの測定チャネル

意味側を、音韻素性とは**別の情報源**から測る。青空文庫コーパスの分布がそれになる。

- **音側**: 音韻素性(語頭子音・母音・形態型・濁音)。表記から決定論的に得る
- **意味側**: コーパス分布。各語の共起語(係る動詞・修飾される名詞・共起形容詞)のベクトル
- **アプリの主張**: 両者の**アラインメント**。音側の構造が意味側の構造を予測できるか

こう置くと検証が非自明になる:

- **O-1'**: 形態バリアント間の**分布的**差異が、パラダイム全体で一貫した方向を向くか。
  「ころっと/ころり」が「ころころ」より瞬間的な文脈に出るのは、素性表ではなく**コーパスが決める**
- **O-2'**: 濁音ペア 20〜25 組の**分布的**差分ベクトルが揃うか。揃えば音象徴、散れば否定的結果
- **O-3'**: ブーバ/キキの予測方向を事前登録し、分布空間で確認する
- **O-5'**: 賢治造語は分布(用例)を持つので、既存語の分布空間に射影できる

そして散布図は「**意味空間に語を置き、音素性で色分けする**」形になる。
色が領域を作れば音象徴が目に見え、混ざれば見えない。どちらでも正直な画が出る。

## 代償

**用例層(コーパス)が v0.2 の装飾ではなく v0.1 の測定器になる**。ループ計画が変わる。
また分布ベクトルは頻度を要求するので、実測 1 の天井(頻度 ≥30 が 119 語)が
そのまま v0.1 の語彙規模になる。コーパス拡大(実測 6)が必須条件に格上げされる。
