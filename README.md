# onomato-atlas — 音象アトラス

近代日本語のオノマトペについて、**音韻素性(音側)と用法分布(意味側)を独立に測り、
両者が一致する範囲を可視化する**静的 Web アプリ。

主張は一文で「**語の音の形は、その語がどんな文脈に出るかを予測する**」。
辞書引きアプリではない。可視化は成果物であって主張ではない。

## なぜ二チャネルなのか

座標を音韻素性から作ると、「形態バリアントは持続軸だけ動く」「濁音は重い方へ動く」は
**構成上の恒真式**になり、何も反証できない。そこで音側と意味側を別々の情報源から測り、
**両者のアラインメント**を主張とする。詳細は `docs/concept.md` §11。

### 品質基準

- **Q-01** 抽出の偽陽性 **2/100**(人手判定・95% 上限 7.0%・合格は上限 10% 未満)
- **Q-02** 軸ごとの密度下限。duration ≥40(458 語・信頼性 0.704)/ roughness ≥120(243 語・0.711)
- **Q-03** 軸採用は二項 p **と** 対照経験 p の両方が α=0.05 未満。`moraic_n` は
  二項 p=1.6e-06 でも対照 p=0.515 で却下した

### 作らなかったもの

較正の結果、**当初の目玉だった「意味の近い語」の地図は載せていません**。
作品を半分に分けて測り直すと、最も近い語が一致するのは 100 回中 12 回しかありませんでした。
F-41(API による語釈生成)と F-42(語感クイズ)もスコープ外に落としました。
理由は SPEC の各項に書いてあります。

## probes/

先行検証に使った使い捨てスクリプト。**本流のパイプラインではない。**

```
probe.py    ABAB 抽出と頻度分布(正規表現のみ)
probe2.py   語境界フィルタの効果測定・品詞分布
probe3.py   意味側特徴量の実現可能性(直後形態素・用言到達率)
probe4a.py  共起キャッシュ生成 → data/cooc.json
probe6.py   語彙構築・PPMI・SVD・O-1/O-2 検定
probe7.py   対照 1(頻度比マッチ)・対照 2(対応シャッフル)・汎化
```

再現には kokoro-graph の `data/bronze`(青空文庫 317 作品・gitignore 対象)が要る。
`data/cooc.json` はそこから生成した中間キャッシュで、リポジトリには含めない。
